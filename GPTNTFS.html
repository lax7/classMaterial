The advent of UEFI firmware with the GPT partitioning scheme replaced the legacy BIOS firmware paired with the MBR partitioning scheme. This transition arose due to limitations in BIOS and MBR, such as MBR's maximum support for 2 terabyte disks and only four partitions, compared to GPT's support for up to 9 zettabytes and 128 partitions. These and other differences have made GPT the preferred choice for modern systems compatible with UEFI firmware. We will take a closer look at the structure of GPT in the next section.

Protective MBR

Ideally, a GPT-partitioned disk should use UEFI firmware. However, some legacy systems still run BIOS firmware even on GPT disks. Since BIOS is designed for MBR, this can cause compatibility issues. To address this, GPT includes a Protective MBR in the first sector of the disk. The Protective MBR signals to BIOS-based systems that the disk uses GPT, preventing misinterpretation or overwriting.

Like the general MBR, the Protective MBR consists of three main components, though with certain differences.

Primary GPT Header

The GPT header acts as a blueprint for the disk's partitions. Every byte in the header serves a specific function. The header occupies the first 92 bytes of a 512-byte sector; the remaining bytes serve as padding. Focus on these initial 92 bytes for meaningful information.

The header comprises 14 fields, each with a unique purpose. Notable fields include:

  • Signature: The value 45 46 49 20 50 41 52 54 identifies the GPT header and is always at the start.
  • Revision: A 4-byte field, typically 00 00 01 00, indicating GPT version 1.0.
  • Header Size: Usually 5C 00 00 00 (92 bytes in decimal, little-endian), representing the header length.

Partition Entry Array

A GPT disk can support up to 128 partitions, and the partition entry array holds information for all of them. Each entry is 128 bytes long. If only six partitions exist, the first six entries will contain partition data, while the remaining 122 entries will be filled with zeros (00).

Backup GPT Header

One significant improvement GPT brings over MBR is redundancy. If the MBR becomes corrupted, recovery is challenging. GPT, in contrast, stores a backup of its header in the last sector of the disk, allowing for recovery if the primary header is damaged. This backup contains the same information as the primary header.

Backup Partition Entry Array

GPT also maintains a backup copy of the partition entry array, located just before the backup GPT header at the end of the disk. This serves as a fail-safe in case the original partition entry array is lost or corrupted.

Threats Targeting GPT

Although GPT enhances efficiency and redundancy compared to MBR, it remains susceptible to certain attacks. Common threats include:

  • Bootkits: Attackers may replace legitimate .efi files in the EFI System Partition (ESP) with malicious bootkits, executing code before the OS loads. UEFI's Secure Boot feature can help prevent such attacks by verifying digital signatures.
  • Ransomware: Some ransomware targets GPT to disrupt the boot process. GPT's backup structures make attacks more challenging, but advanced malware may encrypt the ESP, still hindering booting.
  • Wiper Malware: Sophisticated malware may attempt to encrypt both primary and backup GPT headers and partition arrays or target the ESP directly, making recovery nearly impossible.

Introduction and Learning Objectives

NTFS (New Technology File System) is Microsoft's default file system for Windows operating systems. It is recognized for its robustness, scalability, and advanced features, such as file permissions, encryption, journaling, and support for large files and partitions. NTFS efficiently organizes data and provides valuable forensic insights into system and user activity.

NTFS Components

Before diving into details, it's important to understand the main components of an NTFS disk and their roles in efficient data management and forensic analysis. Key components include:

System Files

NTFS includes several reserved system files critical for internal file system operations:

  • $MFT: Master File Table
  • $MFTMirr: MFT Mirror
  • $LogFile: Transactional log for consistency
  • $Bitmap: Tracks allocated and free clusters
  • $Boot: Stores boot sector information
  • $BadClus: Tracks bad sectors
  • $UpCase: Stores uppercase character mapping for case-insensitive comparisons

From a forensic perspective: $LogFile reveals a history of file system operations; $Bitmap can help identify recent cluster allocations and deletions; $BadClus may expose sectors intentionally marked as bad to hide data.

Master File Table (MFT)

The MFT is the backbone of NTFS, acting as a database storing metadata about every file and directory on the disk. It structures records for both user and system files, supporting comprehensive tracking of disk contents. Key characteristics of the MFT include: Divided into fixed-size (typically 1 KB or 1026 bytes) records; Each file and directory corresponds to an MFT entry; Stores metadata such as timestamps, permissions, and data locations.

$MFTMirr

The $MFTMirr is a mirror of the first few records of the MFT, ensuring redundancy. It provides a backup to recover data if the primary MFT becomes corrupted, thus ensuring file system stability and reliability. It's typically stored in a separate disk area.
