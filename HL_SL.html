Understanding Hard Links vs. Soft Links

To understand links, you first need to know about the Inode.

What is an Inode?
An inode is a data structure on a filesystem that stores everything about a file (size, owner, permissions) except its actual name and the actual data content.

🔗 What is a Hard Link?

A hard link is an additional name for an existing file. It points directly to the inode of the original file.

  • If you delete the original name, the data still exists as long as one hard link remains.
  • It’s like having two different doors that lead to the exact same room.

🔗 What is a Soft Link (Symbolic Link)?

A soft link is a special type of file that points to the path of another file.

  • It does not point to the inode; it points to a filename.
  • If the original file is moved or deleted, the soft link "breaks" because the path it’s looking for is gone.
  • It’s like a post-it note that says, "The files are in the other cabinet."

📊 The Comparison

Feature Hard Link Soft Link (Symlink)
Points to Inode (Actual Data) Path/Filename
File Size Same as the original Very small (just path string)
Cross-Filesystem No (Limited to one disk) Yes
If Original Deleted Data is preserved Link breaks (Dangling link)
Linking Directories Not allowed (usually) Allowed

🔍 Significance for Digital Forensics (2 Points)

For a forensic investigator, links are more than just shortcuts—they are breadcrumbs of user activity:

  • Evidence Recovery & Persistence: Hard links allow an investigator to recover the full content of a "deleted" file if a second link exists elsewhere. Identifying a "Link Count" greater than 1 tells an investigator that the user may have created "ghost" copies to bypass simple deletion.
  • Intent & Attribution: Soft links point to specific paths, helping investigators reconstruct where files used to live (e.g., on a now-removed USB drive), while finding hard links to sensitive files in system directories can prove a user's attempt to hide malicious tools.

🛠 Hands-on Activity (Linux/Mac Terminal) - 12 Points

Try this in your terminal to see the magic happen:

# 1. Create a file
echo "Secret Data" > original.txt

# 2. Create a hard link
ln original.txt hard_link.txt

# 3. Create a soft link
ln -s original.txt soft_link.txt

# 4. Check the inodes (The first number is the Inode)
ls -li

# 5. Delete original and test
rm original.txt
cat hard_link.txt # (This works!)
cat soft_link.txt # (This fails!)

# 6. Forensic Hunt: Create a new file with sensitive content
echo "Sensitive Evidence" > evidence.txt

# 7. Create a "hidden" hard link in another folder
ln evidence.txt /tmp/boring_log.txt

# 8. Check the Inode and Link Count
ls -li evidence.txt
# Note the first number (Inode) and the number '2' (Link Count)

# 9. Find the hidden link by Inode number
# Replace '12345' with the Inode number you saw in step 8
find . -inum 12345 2>/dev/null

# 10. Observe the result
# The terminal will list BOTH evidence.txt and /tmp/boring_log.txt
